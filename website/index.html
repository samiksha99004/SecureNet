About SecureNet

Firewalls and antivirus look for things they already know. SecureNet looks at behaviour: it learns how normal traffic on your computer behaves and raises the alarm when something acts differently — which is how new and unknown attacks are caught.

  1. 1WatchEvery network connection is captured and grouped into “flows”.
  2. 2MeasureEach flow is described by 71 numbers: timing, sizes, flags and rates.
  3. 3JudgeTwo models decide: is this unusual, and if so, which attack is it?
  4. 4WarnYou are alerted instantly and every incident is recorded with a report.

The two models

Detection runs in two stages, so SecureNet can catch attacks it has never seen and still name the ones it knows.

Stage 1 · Is something wrong?

Isolation Forest

An anomaly detector. It builds many random decision trees and measures how quickly a traffic flow can be “isolated” from the rest. Normal traffic looks like everything else and takes many splits; unusual traffic stands out and is isolated in just a few.

Every flow gets an anomaly score. When the score is above the threshold, the flow is flagged as suspicious. Because it learns what normal looks like, it can flag brand-new attacks.

  • Unsupervised
  • Anomaly score
  • Catches unknown attacks

Stage 2 · What kind of attack?

XGBoost

A gradient-boosted tree classifier. It looks at the flows that stage 1 flagged and names the attack category, trained on the CICIDS2018 intrusion dataset — for example DDoS, DoS, brute-force logins, botnets, infiltration and web attacks.

It also reports how confident it is and which traffic features weighed most, so every alert explains why it was raised.

  • Supervised
  • Attack category
  • Confidence & top features

Technology

What happens to a piece of network traffic, step by step — and what each step is built with.

  1. Packet capture

    Packets are read from the network card as they pass, without slowing the connection down.

    • Scapy
    • Npcap
    • Python threads

  2. Flow building

    Packets are grouped into two-way conversations (flows). When a flow ends, 71 features — durations, packet sizes, flags, rates and idle times — are calculated, the same way as the CICIDS2018 dataset.

    • CICFlowMeter-style features
    • NumPy

  3. Stage 1 · Anomaly detection

    The features are scaled exactly as during training and scored by the Isolation Forest. Scores above the threshold are suspicious.

    • scikit-learn
    • Isolation Forest
    • Feature scaling
    • joblib

  4. Stage 2 · Attack classification

    Suspicious flows are classified into attack categories, with a confidence and the features that mattered most.

    • XGBoost
    • CICIDS2018
    • Explainable features

  5. Storage

    Every incident is stored with its score, category, flow details and explanation, in a cloud PostgreSQL database.

    • PostgreSQL
    • Neon cloud
    • SQLAlchemy
    • Alembic

  6. Backend & live stream

    A fast asynchronous API serves the dashboard and pushes live scores and alerts the moment they happen. Accounts are protected with emailed one-time codes and signed tokens.

    • FastAPI
    • WebSockets
    • JWT
    • Email codes

  7. Alerts & reports

    Alerts are grouped into one email per burst with the incident report attached; daily reports are built as text, CSV or PDF; Windows notifications confirm the IDS is running.

    • SMTP email
    • ReportLab PDF
    • Windows notifications

  8. Dashboard

    A modern single-page app shows live charts, incidents, reports and settings — on any screen size, in dark or peach.

    • React
    • TypeScript
    • Vite
    • Recharts
